## 1. 已确认的目标与边界

2026-09-24 用户确认：只开发编译器，不做 RGB，不做已有 BUG 修复；需要测试分支；每次给出测试版本前，必须通过本项目设置的测试，并提供可复制的手动测试指令。

沿用上轮认可的方向：复用 Clang 解析 C++，实现 NutShellGPU 专用代码生成。第一版支持明确的 GPU kernel C++ 子集，不承诺完整 C++ 或 CUDA 工具链兼容。不使用 NVIDIA 计算库。

允许新增：编译器、其头文件、测试、示例、构建/运行适配工具与文档。保持原 `NutShellGPU_sim/`、`NutShellGPU_hw/`、`NutShellGPU_spec/`、原有示例和测试文件内容不变。新增工具只调用现有模拟器公开接口，不复制或替换模拟器执行语义。

本阶段验收对象是编译器及其在现有 FuncSim/CycleSim 上的结果。之前的 RTL 同步升级要求在本阶段暂停：不实现 RTL 功能、不声称生成的通用 kernel 已能在当前 RTL 正确运行。CNN、RGB、训练和底层缺陷修复均不列入本阶段交付。

## 2. 第一版用户体验

输入一个 C++ 源文件和一个明确的 kernel 名称。示意：

```cpp
#include "nutcc.h"

NT_KERNEL void vector_add(const float* a, const float* b,
                          float* out, unsigned int n) {
    unsigned int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) {
        out[i] = a[i] + b[i];
    }
}
```

编译输出为真实 NTAS1 64 位机器指令、可读指令清单、参数和资源元数据。运行适配工具负责加载输入、打包参数、启动现有模拟器和导出输出；不在主机替 kernel 计算结果。CPU 参考只用于测试。

首次可交付版本称为 `nutcc 0.1.0-test.1`，独立于上游 NutShellGPU 的版本号；不把仅新增编译器的分支宣称为完整 GPU 1.2。

## 3. 架构与依赖

流水线：C++ 源码 → Clang 类型 AST → 严格子集检查 → 顺序/谓词化中间表示 → 寄存器分配 → NTAS1 直接编码 → 产物校验。

- 前端：使用外部 `clang++` 完成 C++17 语法、类型检查，以 JSON AST 作为适配接口。接口不是稳定公开 ABI，适配器必须记录版本，首发支持并测试本机 Apple Clang 21.0.0；其他版本未经测试时默认拒绝，不能默默采用不兼容 AST。
- 编译器和测试调度：Python 3.9+ 标准库。不得用正则替代 C++ 类型分析。
- 执行桥接：C++17，链接未修改的 `func_sim.cpp` 与 `cycle_sim.cpp`。构建使用 `-frounding-math -ffp-contract=off`，不启用 fast-math。
- 不依赖 CUDA Toolkit、NVIDIA 库、PyTorch、NumPy 或完整 LLVM 源码构建。无需 CMake；新增构建工具可以直接调用已安装 C++ 编译器。
- 所有外部进程使用参数数组调用，不经 shell 拼接；源文件路径包含空格、中文时仍可使用。

编译期采用自带的小型设备头文件，固定目标类型语义；不导入宿主 STL/系统 ABI。主机 C++ 的指针、结构体布局不能直接作为设备参数布局。

## 4. 语言契约

### 4.1 支持

- 单个入口 `void` kernel；标量参数为 `int`、`unsigned int`、`float`，设备指针指向这些类型或 `unsigned char`，支持只读指针的 `const`。
- `int`/`unsigned int` 为 32 位，`unsigned char` 为 8 位，`float` 为 IEEE binary32。局部标量支持上述类型与 `bool`；局部变量须在读取前初始化。
- 整数加、减、乘，位与/或/异或，比较；无符号右移和左移的有效计数为 0–31。有符号溢出、越界和非法移位仍属于 C++ 未定义行为，不赋予自定义结果。
- FP32 同类型加、减、乘和比较；保持源程序运算顺序，默认不合并为 FMA、不重排。
- 赋值、复合赋值、数组下标、标量局部变量和花括号作用域。
- `threadIdx`、`blockIdx`、`blockDim`、`gridDim` 的 x/y/z，映射到 S2R 特殊寄存器。
- `if/else`，含嵌套条件；逻辑 `&&`、`||` 保留短路语义，右侧访存与副作用必须受正确守卫保护。
- 规范形式的定次数循环：`for (int k = 0; k < C; ++k)`，C 是非负整型编译期常量，循环变量不在循环体内修改、不逃逸。每个循环最多 256 次，嵌套展开后的指令总量最多 4096 条；零次循环不执行循环体。
- 入口末尾可省略 `return;` 或放置一个无条件 `return;`。
- 允许同类型读写、lvalue-to-rvalue、const 调整及 `unsigned char` 到 `int` 的提升。拒绝 `int` 与 `unsigned int` 相互转换、整数窄化及其他数值转换；字节类型首版可以复制和提升，不提供从宽整数截断写入。任何未实现的隐式转换同样报错，不能只检查显式 cast。无符号表达式使用匹配的 `U` 后缀常量，FP32 常量使用 `f` 后缀。

### 4.2 明确拒绝

运行时次数循环、while/do、break/continue、提前 return、goto、switch、普通设备函数调用、递归、模板实例化、类、STL、异常、动态分配、静态可变对象、volatile、原子、shared memory、barrier、warp 原语、多文件链接、内联汇编、64 位整数算术、FP16/FP64、整数与浮点之间转换、除法和取模。

超出资源上限或未能证明符合子集的表达式必须报告文件、行列、具体原因并返回非零。Clang 能解析某种语法不代表 NutCC 支持它。

新发现的底层限制不允许通过修复核心来扩大范围；必须收窄或拒绝相应输入，补充诊断测试，并在交付说明中说明实际支持边界。若需要删除本规格承诺的核心能力，应先明确报告范围变动。

## 5. 在不修复底层 BUG 的条件下生成代码

第一版把条件转换成谓词执行，不发射 SSY/BRA/BRX/CALL/RET 或受条件控制的 EXIT。程序结束只发射一个无条件 EXIT。循环在编译期展开。因此，第一版不宣称已实现一般控制流汇聚后端。

条件只求值一次，then/else 使用同一条件快照，即使 then 内修改参与条件的变量。条件语句的读、写及需要保留旧值的寄存器更新必须有正确守卫；不能只保护最终 store。嵌套条件需保存父条件，与子条件组合，不能在父条件为假时遗留旧谓词。必须验证 `&&`/`||` 不会读取被短路屏蔽的越界地址；NaN 输入下，不能把 `!(a < b)` 错换成 `a >= b`。

生成器使用明确白名单与字段级编码；不依赖现有 `asm_line`。不发射已知有问题的 SETPI、LOP3、XCVT、F16 转换或 `@!PT`，也不依赖尚无执行分支的 PLOP/PSET2。立即数比较使用 MOV32I + SETP；SETP 使用单纯 SET 模式，布尔组合使用普通 GPR 中的 0/1 运算，再转换为执行谓词。恒假代码直接消除、恒真代码无守卫。若某个允许操作不能通过独立参考测试，禁止将它计为支持。

寄存器分配基于已经线性化的指令和保守活跃区间，处理受谓词保护的读改写与旧值保存，复用生命周期不重叠的寄存器。保留 R255 的特殊语义，只分配 R0–R254 与 P0–P6。超限报错，不做未验证的 local-memory spill。必须准确报告每线程寄存器占用。

## 6. 产物、参数与执行接口

每个输出前缀生成三个文件：

1. `.ntbin`：仅含小端 NTAS1 指令字，长度为 8 的倍数。
2. `.json`：`format=nutcc-artifact-v1`、编译器/Clang 版本、源文件与机器码 SHA-256、kernel 名称、目标 profile、指令数、寄存器需求、参数布局和不支持能力列表。
3. `.ntasm`：用于审阅的地址、机器字与可读指令清单，不依赖上游汇编器重新组装才能运行。

目标 profile 为 `ntas1-sim-v1.10-low32-predicated-v1`。这里自定义的是编译器元数据格式，机器指令仍是 NTAS1。

不使用含歧义的上游 `.ntas` 容器 loader，也不把 `.ntbin` 冒充该容器。新增 runner 校验元数据及机器码后，通过现有 `load_code`、`launch` 接口执行。首版每个产物只有一个 kernel，代码入口为 0。

每个参数从 8 字节对齐边界开始，标量按明确的小端 32 位表示，设备指针槽位为小端 u64；总参数区不得超过 4096 字节。编译器和 runner 共用此独立契约，不能 memcpy 宿主 struct 作为参数。

由于现有窄数据 LD/ST 的地址实现限制，实际设备分配和访问范围限定在低 4 GiB。runner 验证分配区间和指针参数不超范围；完整 64 位设备寻址不属于首版。数组访问仍要求源程序合法、用户提供足够缓冲区；不得宣称编译器能静态证明任意下标安全。

runner 支持 `func` 和 `cycle` 两种执行模式，校验 launch 返回值、执行返回码、完成状态和超时。manifest/数据文件输入错误必须干净失败。runner 使用数据文件描述输入输出，不将未受限的路径或输入文本传给 shell。

生成失败时不得留下看似有效的新 manifest。产物先写临时文件，校验后发布；manifest 作为最后提交的完整性标志。已有产物不被失败的编译冒充为本轮成功结果。

## 7. 自动测试与测试版本交付门槛

以下均为必过项，不以截图、单个示例或编译成功代替：

1. 前端正反测试：声明、类型提升、操作优先级、作用域；上述每类不支持语法都有非零退出和定位诊断测试。
2. 编码测试：固定期望机器字与字段；同时用原解码器检查发射白名单和资源合法性。往返编解码不能替代固定期望值。
3. 端到端测试：源文件经过真正编译，产物在 FuncSim 和 CycleSim 分别运行，逐元素对比独立 CPU 参考。两种模拟器共享功能语义，不能只比较二者彼此一致。
4. 覆盖整数向量运算、FP32 向量加法、字节复制、条件选择、then 内修改条件变量、嵌套条件、短路保护、零次/多次展开循环、2D/3D 索引、同缓冲区原地更新与顺序相关写入。
5. 输入规模至少含 1、31、32、33、65、257，覆盖尾 warp 与多 CTA；维度含二维和三维非对称组合。输出前后加哨兵，检查边界线程未写越界。
6. 固定种子随机合法输入；整数逐位比较。浮点基础算术采用明确 binary32 参考，测试有限数、正负零、无穷和 NaN 分类；不要求 NaN payload 一致。常量舍入和非融合表达式单列测试。
7. 负向产物/runner 测试：缺文件、截断指令、错误版本、代码哈希不符、参数大小错误、非法 launch、设备指针超范围、执行失败与超时；任何失败不能变成 PASS。
8. 自动重新构建并运行现有 8 个无第三方依赖 C++ 测试入口：t_decode、t_saxpy、t_diverge、t_runtime_v2、t_timing_v11、t_repairs、t_stats_time、cycle_builtin。它们是回归基线，不证明已修复审计发现的 BUG。
9. 验证原模拟器、RTL、原规范和原测试相对于 `c1b2aed` 无修改；检查输出确定性与含中文/空格路径。

测试由一个入口统一执行，任何必过项失败、未执行或依赖缺失都不得发布测试版本。只允许重跑确认偶发环境问题，不能静默删除失败用例、降低期望或把失败记成通过。

独立的历史 BUG 探针仍归原审计报告，不纳入“本次应修复”清单，也不把它们的预期失败计为编译器通过数。新编译器用例触发缺陷且无法在支持子集内正确生成时，不得交付带有该能力声明的版本。

测试报告记录分支、提交、源码/产物哈希、依赖版本、逐项结果、执行命令和日志路径。每次发布测试版本必须在最终代码提交上重新运行完整门槛，确认没有测试后代码变更，再创建本地测试版本标签；不自动推送。交付包括版本、提交、结果数量、已知限制以及手测命令。

## 8. 手动测试接口约定

以下是待实现的命令契约，当前文件尚不存在，不能现在当作已可运行的指令。

```sh
cd "/Users/molly/projects/GPU编程/NutShellGPU"
git switch test/nutcc-v0.1

# 完整自动验证，成功退出码为 0；报告写入 build/nutcc-test/report.json。
python3 compiler/tests/run_tests.py --all --out build/nutcc-test

# 单独编译一个用户可读的示例。
python3 compiler/nutcc.py compiler/examples/vector_add.cpp \
  --kernel vector_add --out build/nutcc-manual/vector_add

# 使用刚生成的产物，分别运行两个模拟器，并校验输出。
python3 compiler/examples/run_vector_add.py \
  --artifact build/nutcc-manual/vector_add.json --backend func --n 65
python3 compiler/examples/run_vector_add.py \
  --artifact build/nutcc-manual/vector_add.json --backend cycle --n 65
```

示例 runner 必须实际使用 `--artifact` 指定的产物，不偷偷重新生成硬编码 NTAS。输出应含 PASS/FAIL、元素数量、后端、完成状态；失败时退出码非零。交付时按最终实现更新命令，并亲自从干净构建目录逐条执行，避免只给未验证的命令。

## 9. 与书中知识的联系及首版限制

《General-Purpose Graphics Processor Architectures》§2.1 用于线程索引映射；§3.1.1 用于理解逐 lane 条件执行与掩码，首版采用谓词化而非宣称修好了汇聚栈；§3.3 用于寄存器生命周期、资源占用和活跃线程之间的关系。

更完整的 SSY 汇聚后端、运行时循环、spill、寄存器 bank 调度和访存优化是后续编译器扩展，不属于 v0.1 必过指标。首版重点是可解释的机器码、正确类型和内存副作用、可复现的测试。不承诺达到商用编译器优化水平。

## 10. 规格自审

- 上轮的通用 C++ 子集已针对“禁止修底层”收窄，并明确错误诊断。
- 交付目标与原 RTL 计划分开，不暗中修改硬件或宣称 RTL 验证通过。
- 产物与参数契约明确，不沿用已知存在歧义的模块 loader。
- 自动测试和手动测试均有具体输入、通过条件和失败要求。
- 本文件是设计评审材料；用户审阅后才进入实现计划，随后按批准计划开发。
