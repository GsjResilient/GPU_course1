## 计时边界

程序总时间由父进程使用单调高分辨率计时器 `time.perf_counter` 测量，从创建模拟器子进程之前到子进程退出之后。包括启动、输入与权重/指令装载、模拟器初始化、执行、逐层张量导出、统计输出和退出。编译、夹具生成、独立参考计算及正确性检查位于计时区间之外。

程序总时间是宿主进程的墙钟时间；模拟周期是虚拟 GPU 的推进计数；GPU 执行时间是实际设备执行内核的耗时。三者分别记录。所有模拟延时为模拟值。

`core_clock_ghz` 默认 1.0，对应第 00 册的 `gpu_clock = 1000 MHz`。纳秒延迟按 `ceil(ns × GHz)` 换算为周期；虚拟时间为 `cycles / (core_clock_ghz × 10^9)`，与宿主墙钟时间分别统计。

`simulated_seconds` 只覆盖 CycleSim 计入的虚拟 GPU 周期，不包含宿主文件读取、程序初始化或结果导出等未建模工作。

配置采用混合单位，所有值均为模拟值：

| 参数类别 | 单位 | 默认示例 |
|---|---|---|
| 执行单元 latency、发射 interval | 周期 | FP32 4 周期、整数乘法 4 周期 |
| shared/L1/L2/DRAM 基础延迟 | 纳秒，经核心频率换算 | 2/30/180/400 ns |
| NoC link/router 与资源仲裁等待 | 周期 | 由配置及冲突状态确定 |
| 核心频率 | GHz | 1.0 |

更改频率会改变按纳秒给定的延迟对应的周期数；按周期给定的执行单元延迟仍保留其周期数。

## 使用

```sh
python NutShellGPU_sim/tests/benchmark_process.py --runner build/model_runner --fixture fixture_directory --out process_measurements --repeats 3
python NutShellGPU_sim/tests/check_model.py fixture_directory process_measurements/run0
```

计时入口仅依赖 Python 标准库，正确性检查另需 NumPy。Windows 的 runner 可指定 `build/Release/model_runner.exe`。每次运行创建新进程，使用模拟器默认配置，不清理操作系统文件缓存，操作系统文件缓存状态影响墙钟结果。

`runtime.json` 保存样本数、平台、可执行文件与夹具 SHA-256、每次实际秒数、退出码、模拟周期、虚拟频率、模拟秒数及实际时间中位数。`stats.json` 也输出 `simulated_seconds`，使用高精度科学记数格式保留小于一纳秒的非零值。程序失败立即保留已采集的记录并报错，不将失败耗时作为成功结果。原始日志及模型输出在各 run 子目录。
